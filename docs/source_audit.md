# Public ArduPilot source profile

Supported profile: **ArduCopter V4.8.0-dev, public commit `2b5cebb933d91e92f7bab768268e41c2960b6ae4`**. This document audits public source-code semantics only. It contains no flight telemetry or inspection results. Presence, rates, timing, values and configuration must be independently verified for each input log.

## Critical acceleration distinction

At this exact revision, `PSCN.AN` and `PSCE.AE` are calculated from **attitude-controller target roll/pitch**, using current AHRS yaw and gravity-based tilt geometry. They are not independently measured horizontal acceleration. `write_log()` calls `lean_angles_to_accel_NE_mss()`; that helper reads `get_att_target_euler_rad()`, substitutes `_ahrs.yaw`, then converts the angles. `TAN/TAE` are the position-controller acceleration target after feedback/feedforward combination and lean-angle limiting.

Consequently, horizontal `A - TA` is a residual between two signals inside the command/control stack. Calling it measured acceleration minus command, external disturbance, aerodynamic drag, or wind would not follow from these fields. This is a scientific interpretation issue, even if the subtraction and units are correct. [Exact logging path](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/AC_PosControl.cpp#L1504-L1534), [target-angle conversion](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/AC_PosControl.cpp#L1626-L1634), [target composition](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/AC_PosControl.cpp#L697-L796).

The vertical channel has different provenance: `PSCD.AD` is `AHRS.get_accel_ef().z + g`, an Earth-frame, gravity-compensated, down-positive acceleration estimate in m/s². It must not be presented as having the same measurement provenance as horizontal `AN/AE`. [Exact accessor](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/AC_PosControl.h#L605-L611).

## PSC schema and frames

| Message | Axis | Fields after TimeUS |
|---|---|---|
| PSCN | North | DPN, TPN, PN, DVN, TVN, VN, DAN, TAN, AN |
| PSCE | East | DPE, TPE, PE, DVE, TVE, VE, DAE, TAE, AE |
| PSCD | Down | DPD, TPD, PD, DVD, TVD, VD, DAD, TAD, AD |

`D` prefixes mean desired; `T` means target; the unsuffixed quantity is the logged controller state/estimate, subject to the acceleration exception above. Position is in meters relative to navigation/EKF origin; velocity is m/s; acceleration is m/s². This is NED: positive vertical values are downward. `TimeUS` is microseconds since startup. The format is `Qfffffffff`, units `smmmnnnooo`, multipliers `F000000000`. Read the actual log's FMT/FMTU/UNIT/MULT rather than assigning formats from this note. Header descriptions of desired position and offsets are inconsistent across axes; source computation is authoritative. [Pinned field declarations and metadata](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/LogStructure.h#L15-L52), [format entries](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/LogStructure.h#L178-L192).

The writer assigns SI arguments directly, and obtains a separate `micros64()` timestamp for each PSC message. Thus N/E/D packets need not share precisely equal timestamps. [Pinned PSC writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AC_AttitudeControl/AC_PosControl_Logging.cpp).

## Attitude and EKF

`ATT.Yaw` is canonical AHRS yaw converted to degrees and wrapped into [0,360); `ATT.AEKF` records active estimator type. It is vehicle attitude, not course over ground. [Pinned ATT writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_AHRS/AP_AHRS_Logging.cpp#L62-L76). ArduPilot heading convention is North=0°, East=90°, increasing clockwise. [Official heading convention](https://ardupilot.org/copter/docs/mission-command-list.html#waypoint). A yaw-only NED-to-horizontal-heading rotation is `forward = cos(yaw)*N + sin(yaw)*E`, `right = -sin(yaw)*N + cos(yaw)*E`; this is a level heading frame, not a full tilted body-frame rotation. The transformation is a mathematical consequence of that convention. Unwrap angular values within continuous segments before interpolation.

`XKF1.C` identifies the EKF3 core. `PN/PE/PD` are NED position in meters; `VN/VE/VD` are NED velocity in m/s; `dPD` is a separate filtered vertical-position derivative. The writer uses output getters, not raw delayed state-vector elements. `XKF4.C` likewise identifies the logged core, while `XKF4.PI` identifies the selected primary core. [Pinned EKF writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF3/AP_NavEKF3_Logging.cpp#L15-L54), [primary-core logging](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF3/AP_NavEKF3_Logging.cpp#L141-L182).

These output getters correct velocity/position for IMU-to-body-origin offsets. Position references the public navigation origin, with local-origin correction. In constant-position/invalid states the position getter can emit fallback or zero values while returning false; the log writer does not encode that return value. Health/status therefore matters. `XKF4.OFN/OFE` is the **last position-reset delta**, not a pulse indicating a new reset each row. `SV/SP/SH/SVT` are square roots of innovation test ratios in actual code, despite imprecise variance wording in generated documentation; they are not position/velocity standard deviations. [Pinned getters and test-ratio outputs](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF3/AP_NavEKF3_Outputs.cpp#L175-L287), [reset delta and ratios](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF3/AP_NavEKF3_Outputs.cpp#L473-L488).

Relevant `XKF4` fields: `FS` fault bits, `TS` timeout bits, `SS` solution bits, `GPS` GPS-check status, `PI` primary core. Timeout bits 0..5 correspond to position, velocity, height, magnetometer, airspeed, drag. [Pinned EKF log definitions](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF3/LogStructure.h).

Useful solution masks are attitude=1, horizontal velocity=2, vertical velocity=4, relative horizontal position=8, absolute horizontal position=16, vertical position=32; constant-position=128; GPS glitch=16384; dead-reckoning=262144. Do not require GPS-only validity for non-GPS flights. [Pinned status definition](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF/AP_Nav_Common.h#L26-L45).

Fault masks are bad quaternion=1, bad velocity=2, bad X/Y/Z magnetometer measurements=4/8/16, bad airspeed=32, bad synthetic sideslip=64, uninitialized=128. Zero means none of these faults are flagged; it is not a complete estimator-quality certificate. [Pinned fault definition](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_NavEKF/AP_Nav_Common.h#L75-L87).

`GPS.Status` references `AP_GPS_FixType`: 0 absent, 1 no lock, 2 2D, 3 3D, 4 differential 3D, 5 RTK float, 6 RTK fixed, 7 static (typically base station), 8 PPP. Unknown values must remain unknown rather than automatically pass a `>=3` check. A fix category alone does not establish accuracy or EKF validity. [Pinned fix enum](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_GPS/AP_GPS_FixType.h), [GPS log field](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_GPS/LogStructure.h#L17-L22).

Validator design implication: never pool different `C` streams; select `C==PI` only with time-aligned primary metadata, or expose a deliberate fixed-core choice. Core changes, source changes, reset events, and detected discontinuities are segment boundaries. A change in OFN/OFE is only a reset candidate; identical repeated reset deltas cannot be detected from those fields alone. Absence of reset evidence is not proof of absence.

## Arming and event context

`ARM` is an arming-state-change record: `ArmState` is the new armed state, `ArmChecks` is the configured arming-check mask, `Forced` indicates a forced transition, and `Method` records the cause/method. It does not prove takeoff, and the check mask is not a per-check pass/fail result. [Pinned ARM definitions](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_Logger/LogStructure.h#L683-L691).

Documented `EV` values include armed=10, disarmed=11, land-complete=18, not-landed=28, EKF-alt-reset=60, EKF-yaw-reset=62, and EKF-source-set selections=85/86/87. Preserve unknown IDs as raw values and use events as evidence, not complete coverage. [Official event reference](https://ardupilot.org/copter/docs/logmessages.html#ev).

## Output and ESC identity

`SERVOx_FUNCTION` associates output channel x with a logical function. Motor1..8 are 33..40, Motor9..12 are 82..85, Motor13..32 are 160..179. A physical output number is not inherently its logical motor number. [Pinned function enum](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/SRV_Channel/SRV_Channel.h#L82-L89), [additional motors](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/SRV_Channel/SRV_Channel.h#L126-L129), [Motor13 onward](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/SRV_Channel/SRV_Channel.h#L192-L211). Functions may be assigned to multiple outputs, so preserve many-to-one mappings rather than silently overwrite them. Geometry also depends on frame class/type; use the logged frame information for each dataset. [Official output mapping](https://ardupilot.org/copter/docs/common-rcoutput-mapping.html#the-servon-function-parameters).

`ESC.Instance` is zero-based. `RPM` is slewed between previous/current backend readings and may include a scripting scale factor; `RawRPM` is the unslewed backend reading. Missing/invalid RPM produces NaN, and logging occurs on RPM or other telemetry updates, so equal values do not establish equal sensor-update times. Preserve both original columns and never silently replace zeros or NaNs. The logger contains an eRPM comment that is misleading for backends already doing mechanical conversion. [Pinned ESC getters](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_ESC_Telem/AP_ESC_Telem.cpp#L183-L228), [logger](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_ESC_Telem/AP_ESC_Telem.cpp#L672-L717).

For BLHeli serial telemetry, the backend converts its incoming electrical rate using `200 / motor_poles` before storing RPM, and maps the instance to output-channel index. [Pinned BLHeli conversion](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_BLHeli/AP_BLHeli.cpp#L1543-L1548). Bidirectional DShot similarly converts before `update_rpm`. [Pinned DShot conversion](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_HAL_ChibiOS/RCOutput_bdshot.cpp#L855-L862). Therefore do not divide logged `RawRPM` by pole pairs again. Correctness of shaft speed still depends on the configured pole count and backend. [Official pole-count explanation](https://ardupilot.org/copter/docs/common-esc-telemetry.html#connecting-the-escs-telemetry-wire).

Unresolved until log/config inspection: exact ESC transport and identity mapping, actual pole count, script scaling, valid airborne periods, health-flag coverage, reset-event completeness, and time alignment/error bounds. None should be filled with assumed vehicle defaults.

## No-multiplier sentinel and actuator/throttle scaling

ArduPilot defines multiplier ID `-` with numeric value zero as **no multiplier**; it is a sentinel, not an instruction to multiply numeric data by zero. ID `?` means the multiplier has not been established; ID `0` explicitly means a factor of one. Unit ID `-` separately means no unit, while unit ID `?` means unknown. Preserve the original IDs and MULT values in provenance. For the source-verified numeric fields below, `-` requires no numerical scaling. Unknown or absent metadata must remain separately identified. [Pinned multiplier documentation](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_Logger/README.md#L83-L99), [unit/sentinel definitions](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_Logger/LogStructure.h#L44-L99).

`RCOU.C1` onward are unsigned output-channel values copied from `hal.rcout->read()` without scaling. Metadata uses unit `Y` (microseconds) and multiplier `-`. Preserve these values as PWM-style microseconds. For digital protocols such as DShot, **PWM-equivalent output command** is the accurate physical description: the ChibiOS driver stores the input PWM value and maps it to a DShot command later. It is not a measured pulse width, rotor speed, or thrust. [Pinned RCOU writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_Logger/LogFile.cpp#L191-L217), [readback](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_HAL_ChibiOS/RCOutput.cpp#L856-L901), [DShot conversion](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_HAL_ChibiOS/RCOutput.cpp#L1701-L1709).

`CTUN.ThO` is written directly from `motors->get_throttle()`. That accessor returns filtered motor-controller throttle constrained to `[0,1]`. Export the original float as a dimensionless ratio; multiplying by 100 is appropriate only for a separately labelled percentage display. It is not a PWM output or measured thrust. CTUN metadata intentionally supplies unit `-` and multiplier `-` for this field. [Pinned CTUN writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/ArduCopter/Log.cpp#L53-L59), [CTUN metadata](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/ArduCopter/Log.cpp#L486-L487), [exact constrained accessor](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_Motors/AP_Motors_Class.h#L154-L159).

`ESC.Volt` and `ESC.Curr` are directly logged backend values in volts and amperes despite multiplier `-`; no extra factor is needed. This DataFlash representation differs from the separately scaled integer MAVLink ESC messages. Field presence or zero values alone do not establish sensor availability or freshness. [Pinned ESC writer and units](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_ESC_Telem/AP_ESC_Telem.cpp#L695-L715), [ESC metadata](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_ESC_Telem/LogStructure.h#L62-L65). `BAT.Curr` is likewise amperes, explicitly multiplier `0` = one; its writer uses the backend current value or NaN when current sensing is unavailable. [Pinned BAT writer](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_BattMonitor/AP_BattMonitor_Logging.cpp#L27-L41), [BAT metadata](https://github.com/ArduPilot/ardupilot/blob/2b5cebb933d91e92f7bab768268e41c2960b6ae4/libraries/AP_BattMonitor/LogStructure.h#L64-L66).
